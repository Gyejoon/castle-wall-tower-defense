# Impeccable 디자인 스킬 사용 가이드

## 개요

Impeccable은 Claude Code에 설치된 **디자인 품질 관리 스킬 시스템**입니다. 20개의 전문 스킬이 UI/UX의 다양한 측면을 담당하며, 슬래시 커맨드(`/audit`, `/polish` 등)로 호출합니다. 여기에 게임 프로젝트 전용 `/game-ui-design` 스킬이 추가로 설치되어 있습니다.

모든 스킬은 `.impeccable.md`에 정의된 프로젝트 디자인 컨텍스트를 참조하여 일관된 디자인 판단을 내립니다.

---

## 초기 셋업

### `/teach-impeccable` (한 번만 실행)

프로젝트의 디자인 컨텍스트를 수집하여 `.impeccable.md`에 저장합니다.

```
/teach-impeccable
```

생성되는 `.impeccable.md` 내용:
- 사용자 & 목적
- 브랜드 개성
- 미학 방향
- 색상 토큰
- 기술 제약
- 디자인 원칙

> 이미 `.impeccable.md`가 있으면 이 단계는 건너뛰세요.

## 스킬 카탈로그

### 평가/분석 스킬

| 커맨드 | 용도 | 사용 시점 |
|--------|------|-----------|
| `/audit` | 기술 품질 감사 (접근성, 성능, 테마, 반응형, 안티패턴) | 기능 완성 후 품질 점검 |
| `/critique` | UX 디자인 평가 (휴리스틱 점수, 페르소나 테스트) | 디자인 리뷰, 피드백 요청 |

### 레이아웃/비주얼 스킬

| 커맨드 | 용도 | 사용 시점 |
|--------|------|-----------|
| `/arrange` | 레이아웃, 간격, 시각적 리듬 개선 | 레이아웃이 어색하거나 빽빽할 때 |
| `/colorize` | 전략적 색상 추가 | 단색적이거나 밋밋할 때 |
| `/typeset` | 타이포그래피 개선 (폰트, 계층, 가독성) | 텍스트가 어색하거나 읽기 어려울 때 |
| `/animate` | 애니메이션, 마이크로 인터랙션 추가 | UI에 생동감을 더하고 싶을 때 |

### 톤 조절 스킬

| 커맨드 | 용도 | 사용 시점 |
|--------|------|-----------|
| `/bolder` | 밋밋한 디자인 강화 | 디자인이 너무 안전하거나 개성 없을 때 |
| `/quieter` | 과도한 자극 완화 | 디자인이 공격적이거나 시끄러울 때 |

### UX/콘텐츠 스킬

| 커맨드 | 용도 | 사용 시점 |
|--------|------|-----------|
| `/clarify` | UX 카피, 에러 메시지 개선 | 텍스트가 혼란스러울 때 |
| `/delight` | 즐거움과 개성 추가 | 기능적이지만 재미없을 때 |
| `/distill` | 불필요한 복잡성 제거 | UI가 복잡하거나 산만할 때 |
| `/onboard` | 온보딩, 빈 상태 설계 | 첫 사용자 경험 개선 |

### 기술/시스템 스킬

| 커맨드 | 용도 | 사용 시점 |
|--------|------|-----------|
| `/adapt` | 반응형 디자인, 다중 디바이스 적응 | 모바일/태블릿 대응 |
| `/harden` | 에러 처리, i18n, 엣지 케이스 | 프로덕션 준비 |
| `/optimize` | UI 성능 최적화 | 느리거나 버벅거릴 때 |
| `/extract` | 재사용 컴포넌트/토큰 추출 | 디자인 시스템 정리 |
| `/normalize` | 디자인 시스템 표준 정렬 | 스타일 불일치 수정 |
| `/overdrive` | 극한 인터랙션 (셰이더, 물리) | 와우 효과가 필요할 때 |

### 코어 스킬

| 커맨드 | 용도 | 사용 시점 |
|--------|------|-----------|
| `/frontend-design` | 프론트엔드 인터페이스 제작 | 새 컴포넌트/페이지 구현 |
| `/polish` | 출시 전 최종 품질 패스 | 모든 수정 후 마지막 단계 |

## 워크플로우 예시

### 1. 새 UI 컴포넌트 개발

```
/frontend-design HUD 패널    ← 컴포넌트 구현
/audit HUD 패널              ← 기술 품질 점검
/polish HUD 패널             ← 마무리
```

### 2. 출시 전 QA 파이프라인

```
/critique 메인 화면           ← UX 전체 평가 (점수 + 이슈 목록)
/audit 메인 화면              ← 기술 감사
                              ← audit/critique가 추천하는 스킬 순서대로 실행
/polish 메인 화면             ← 최종 마무리
/critique 메인 화면           ← 점수 재확인
```

### 3. 디자인 개선 (특정 이슈)

```
"레이아웃이 답답해" → /arrange
"색이 밋밋해"      → /colorize
"글자가 읽기 어려워" → /typeset
"너무 화려해"      → /quieter
"개성이 없어"      → /bolder
"에러 메시지가 불친절해" → /clarify
```

### 4. 연쇄 사용 (audit/critique 결과 기반)

`/audit`이나 `/critique`를 실행하면 리포트 끝에 **추천 액션**이 나옵니다:

```
추천 액션:
1. [P0] /arrange — 터치 타겟 44px 미달
2. [P1] /colorize — 대비 부족
3. [P2] /clarify — 에러 메시지 개선
4. [P3] /polish — 최종 마무리
```

이 순서대로 실행하면 체계적으로 품질을 개선할 수 있습니다.

## `.impeccable.md` 커스터마이징

프로젝트 루트의 `.impeccable.md`를 직접 편집하거나 `/teach-impeccable`을 재실행하세요.

### 주요 섹션

| 섹션 | 역할 |
|------|------|
| Users & Purpose | 타겟 사용자, 핵심 태스크 |
| Brand Personality | 브랜드 톤, 레퍼런스, 안티레퍼런스 |
| Aesthetic Direction | 색상 모드, 폰트, 그리드 |
| Color Tokens | 디자인 토큰 팔레트 |
| Tech Constraints | 기술 스택, 성능 제약 |
| Guiding Principles | 디자인 판단 기준 |

이 파일을 수정하면 **모든 impeccable 스킬**의 판단 기준이 변경됩니다.

## 팁

- `/audit`과 `/critique`는 **보고만** 합니다 — 수정은 다른 스킬이 담당
- `/polish`은 항상 **마지막에** 실행 (기능이 완성된 후)
- 여러 스킬을 한 번에 실행하고 싶으면 "audit 결과를 기반으로 모두 실행해줘"라고 요청
- 각 스킬은 `/frontend-design`을 내부적으로 참조하므로 디자인 원칙이 자동 적용됨
