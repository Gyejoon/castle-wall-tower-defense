# 2.5D Asset Pipeline Design

## Context

Grid Line Defense PvP is a Phaser 3 tower defense game with 32x32 pixel art assets (medieval fantasy theme). Assets are currently generated procedurally via `@napi-rs/canvas` + Bun scripts with basic 2.5D shading (shadow ellipses, depth highlights). The goal is to upgrade all assets to proper 2.5D quality using AI image generation tools controllable via MCP, while maintaining style consistency across all asset types.

## Approach: Hybrid Pipeline (ComfyUI + PixelLab + Procedural)

Use the right tool for each asset type:
- **ComfyUI MCP** (local, free) for tiles and towers — ControlNet ensures structural consistency
- **PixelLab MCP** (cloud API, affordable) for animated characters — purpose-built for directional pixel art sprites
- **Existing procedural scripts** for VFX, projectiles, UI — current canvas scripts are sufficient

## Architecture

```
Claude Code (MCP Client)
    |
    +-> ComfyUI MCP Server (localhost:8188)
    |     +-- Tiles: ControlNet Tile model for seamless patterns
    |     +-- Towers: Canny edge (silhouette) + IP-Adapter (style ref)
    |     +-- Environment: Decorations, tileset
    |
    +-> PixelLab MCP Server (cloud, api.pixellab.ai)
    |     +-- Units: 4/8-direction walk cycles
    |     +-- Unit animations: attack, death
    |     +-- Unit icons
    |
    +-> Asset Post-Processor (local Bun script)
          +-- Downscale to 32x32 (nearest-neighbor)
          +-- Palette unification (map to shared.ts PALETTE)
          +-- Spritesheet assembly (4-frame = 128x32)
          +-- asset-manifest.json update
          +-- Output to /packages/web-shell/public/assets/
```

## MCP Server Configuration

### ComfyUI MCP

```json
{
  "mcpServers": {
    "comfyui": {
      "command": "npx",
      "args": ["-y", "comfyui-mcp"],
      "env": {
        "COMFYUI_URL": "http://localhost:8188"
      }
    }
  }
}
```

Required models:
- `retro-diffusion/rd_pro__isometric` — isometric pixel art specialized
- ControlNet Tile — tile pattern consistency
- ControlNet Canny — structure control from existing silhouettes
- IP-Adapter — style reference injection for palette/texture unity

### PixelLab MCP

```json
{
  "mcpServers": {
    "pixellab": {
      "command": "npx",
      "args": ["-y", "@pixellab/mcp-server"],
      "env": {
        "PIXELLAB_API_KEY": "${PIXELLAB_API_KEY}"
      }
    }
  }
}
```

Key API endpoints:
- `generate_character` — 4/8 directional character sprites
- `generate_animation` — walk/attack/death animation sequences
- `style_match` — match existing asset style

## Asset Generation Strategy

| Asset Type | Count | Tool | Prompt Strategy | Post-Processing |
|-----------|-------|------|----------------|-----------------|
| Tiles (floor, path, spawn, exit) | 4 | ComfyUI | `"medieval grass/path/stone tile, top-down isometric, seamless"` + ControlNet Tile | 32x32 resize, palette map |
| Towers (laser→archer, plasma→catapult, etc.) | 9 static + 9 fire anim | ComfyUI | Existing tower silhouette as Canny edge + `"medieval [type] tower, isometric"` + IP-Adapter style ref | 32x32 resize, palette map, 4-frame fire spritesheet |
| Units (scout→goblin, battle→orc, etc.) | 5 walk cycles + death | PixelLab | `generate_character(directions=4, style="medieval_fantasy", size=32)` | Palette map, 128x32 spritesheet assembly |
| Projectiles | 3 + hit flash | Procedural (keep) | Current canvas scripts | No change |
| VFX | 4 | Procedural (keep) | Current canvas scripts | No change |
| UI | All | Procedural (keep) | Current canvas scripts | No change |

## Post-Processor Design

Location: `scripts/generate-assets/ai-post-process.ts`

```typescript
// Pipeline:
// 1. Load AI-generated image (PNG from ComfyUI/PixelLab output dir)
// 2. Map colors to medieval fantasy palette (shared.ts PALETTE)
//    - Euclidean distance in RGB space for nearest color
//    - Optional Floyd-Steinberg dithering toggle
// 3. Nearest-neighbor resize to 32x32 (preserves pixel art crispness)
// 4. Assemble spritesheet if animation (4 frames = 128x32)
// 5. Add entry to asset-manifest.json
// 6. Save to /packages/web-shell/public/assets/[category]/
```

Palette unification ensures ComfyUI and PixelLab outputs share the same color vocabulary:
- `gridDark: '#5a8a30'`, `gridLight: '#7ab648'`
- `dirtPath: '#b8956a'`, `stone: '#8c8c8c'`
- `ice: '#a8def0'`, `fireOrange: '#e07020'`
- Plus character-specific colors from existing unit palette

## Style Consistency Strategy

1. **Style Reference Image:** Create one "golden" reference sprite that defines the target 2.5D aesthetic. Use as IP-Adapter input for ComfyUI and style_match input for PixelLab.
2. **ControlNet Structure:** Use Canny edges from existing procedural sprites as structural guides — AI fills in detail while maintaining proportions.
3. **Palette Lock:** Post-processor forces all outputs into the fixed medieval fantasy palette.
4. **Review Gate:** Each generated asset is displayed for visual review before committing to the asset directory.

## File Structure (New)

```
scripts/generate-assets/
    +-- ai-generate-all.ts        (orchestrator for AI pipeline)
    +-- ai-generate-tiles.ts      (ComfyUI tile generation)
    +-- ai-generate-towers.ts     (ComfyUI tower generation)
    +-- ai-generate-units.ts      (PixelLab unit generation)
    +-- ai-post-process.ts        (palette unification + resize)
    +-- ai-config.ts              (prompts, model configs, paths)
    +-- shared.ts                 (existing, reuse PALETTE)
    +-- generate-all.ts           (existing procedural, kept)
```

## Verification Plan

1. **Style consistency test:** Place AI-generated assets alongside procedural assets in-game, verify no visual clash
2. **Pipeline E2E test:** Run `bun run scripts/generate-assets/ai-generate-all.ts` end-to-end
3. **Asset spec compliance:** Verify all outputs match existing specs (32x32, correct frame counts, PNG format)
4. **MCP connection test:** Confirm ComfyUI and PixelLab MCP tools callable from Claude Code
5. **Phaser loading test:** Run the game, verify Preloader loads AI-generated assets without errors
6. **Palette audit:** Script to verify all pixels in generated assets fall within the defined palette
