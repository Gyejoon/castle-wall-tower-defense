# 덱 시스템 설계 문서

**상태:** 다음 세션에서 구현 예정
**선행 작업:** PVE Phase 0 완료 (10웨이브, 에너지 경제)
**GDD 근거:** 일반모드 게임 설계 문서 6-1절

---

## 1. 현재 상태 (제거 대상)

| 시스템 | 파일 | 설명 |
|--------|------|------|
| RandomTowerSystem | `systems/RandomTowerSystem.ts` | 에너지 10 소비 → 랜덤 타워 1개 롤 |
| MergeSystem | `systems/MergeSystem.ts` | 같은 defId + tier 타워 2개 드래그 합성 |
| 롤 버튼 | `scenes/Game.ts` hudBuyBtn | "타워 롤 10E" 캔버스 버튼 |
| 카드 선택 없음 | - | 플레이어에게 타워 선택권 없음 |

**제거 이유:** 랜덤 롤이 PVE에서 전략성 없음 (사용자 판단). GDD도 덱 선택을 정의.

---

## 2. 목표 시스템: 4타워 덱

### 2-1. 핵심 흐름

```
로비 → 보유 타워 중 4개 덱 편성 → 전투 진입
전투 중 → 하단 4개 카드 표시 → 카드 탭 → 에너지 소비 → 타일에 배치
```

### 2-2. 4타워 역할군 (GDD 6-1-1)

| 역할군 | 용도 | 에너지 비용 | 특성 |
|--------|------|------------|------|
| 집중 공격형 | 보스/고HP 적 처리 | 10 | 단일 타겟 고데미지 |
| 다중 공격형 | 일반몹 처리 | 10 | 다중 타겟 / splash |
| 슬로우 | 이동 지연 | 20 | 쿨타임 기반, 중복 불가 |
| 스턴 | 이동 정지 | 20 | 쿨타임 기반, 중복 불가 |

> 같은 역할군 중복 편성 가능. 4슬롯 모두 공격형도 허용.

### 2-3. 에너지 비용 체계

- 공격형(집중/다중): 에너지 10
- CC형(슬로우/스턴): 에너지 20
- 동일 타워 중복 배치 가능
- 배치 횟수 제한 없음 (에너지가 있으면 무한 배치)

### 2-4. 전투 중 UI (GDD 8절)

```
┌─────────────────────────────┐
│  [HP] [에너지⚡] [웨이브]    │  ← 기존 HUD (변경 없음)
├─────────────────────────────┤
│                             │
│         게임 그리드          │
│                             │
├─────────────────────────────┤
│ [카드1] [카드2] [카드3] [카드4] │  ← 새로운 덱 카드 UI
│  10E     10E     20E    20E  │
└─────────────────────────────┘
```

- 카드 탭 → 타워 선택 상태 → 타일 탭으로 배치
- 에너지 부족 시 카드 흐릿하게 표시
- 배치 후 카드 재사용 가능 (쿨다운 없음, 에너지만 충분하면)

## 3. 구현 범위

### Phase 1A: 전투 중 덱 카드 (이번 구현)

1. **RandomTowerSystem 제거** + MergeSystem 제거
2. **DeckSystem 생성** — 4개 타워 defId를 받아 관리
3. **덱 카드 UI** — 하단 4개 카드 (React DOM 또는 Phaser UI)
4. **배치 흐름** — 카드 탭 → 타워 선택 → 타일 탭 → 에너지 소비 → 배치
5. **에너지 비용 분기** — 공격형 10E / CC형 20E

### Phase 1A에서 하지 않는 것

- 로비 덱 편성 UI (하드코딩 4개로 시작)
- 속성 시스템
- 타워 승급/강화
- 합성

### 하드코딩 기본 덱 (Phase 1A)

```typescript
const DEFAULT_DECK = [
  'flame_turret',     // 집중 공격형, 화, 10E
  'inferno_tower',    // 다중 공격형, 화, 10E
  'frost_obelisk',    // 슬로우, 수, 20E
  'lightning_beacon',  // 스턴(?), 번개, 20E — 스턴 타워 확인 필요
];
```

> 타워 18종 중 역할군별 1개씩 선택. 기존 TowerDef에 `role` 필드 추가 필요.

## 5. 의사결정 필요 사항

다음 세션 시작 시 확인:

1. **하드코딩 덱 구성** — 4개 타워 조합 확정 (현재 18종 중 선택)
2. **CC형 비용 20E** — GDD 기준이지만, 에너지 1/sec에서 20E는 20초 대기. 밸런스 확인 필요
3. **카드 UI 위치** — Phaser 캔버스 내부 vs React DOM 오버레이
4. **TowerDragController** — 합성 제거 후 판매만 남김? 아니면 드래그 배치도 제거?

## 6. 검증 계획

1. 4개 카드가 하단에 표시되는가
2. 에너지 부족 시 카드가 비활성화되는가
3. 카드 탭 → 타일 탭으로 배치가 되는가
4. 공격형 10E / CC형 20E가 정확히 소비되는가
5. 같은 타워 무한 배치가 되는가 (에너지만 충분하면)
6. 10웨이브 한 판이 5~7분 내에 플레이 가능한가
7. 합성/랜덤 롤 흔적이 완전히 제거되었는가
