이 스킬은 뻔한 "AI 양산형(AI slop)" 미학을 피하는 차별화된 프로덕션 수준의 프론트엔드 인터페이스 제작을 안내합니다. 미적 디테일과 창의적 선택에 뛰어난 주의를 기울여 실제 작동하는 코드를 구현합니다.

## 컨텍스트 수집 프로토콜

디자인 스킬은 프로젝트 컨텍스트 없이는 뻔한 결과물을 만들어냅니다. 디자인 작업 전에 반드시 디자인 컨텍스트를 확보해야 합니다.

**필수 컨텍스트** — 모든 디자인 스킬에 최소한 다음이 필요합니다:
- **타겟 사용자**: 이 제품을 누가, 어떤 맥락에서 사용하는가?
- **사용 사례**: 사용자가 달성하려는 과제는 무엇인가?
- **브랜드 개성/톤**: 인터페이스가 어떤 느낌이어야 하는가?

개별 스킬마다 추가 컨텍스트가 필요할 수 있습니다 — 해당 스킬의 준비 섹션을 확인하세요.

**핵심**: 코드베이스를 읽는 것만으로는 이 컨텍스트를 유추할 수 없습니다. 코드는 무엇이 만들어졌는지 알려줄 뿐, 누구를 위한 것인지나 어떤 느낌이어야 하는지는 알려주지 않습니다. 오직 제작자만이 이 컨텍스트를 제공할 수 있습니다.

**수집 순서:**
1. **현재 지시사항 확인 (즉시)**: 로드된 지시사항에 **Design Context** 섹션이 이미 있으면 바로 진행합니다.
2. **.impeccable.md 확인 (빠름)**: 지시사항에 없으면 프로젝트 루트의 `.impeccable.md`를 읽습니다. 필수 컨텍스트가 포함되어 있으면 진행합니다.
3. **/teach-impeccable 실행 (필수)**: 어느 소스에도 컨텍스트가 없으면, 다른 작업 전에 반드시 /teach-impeccable을 실행해야 합니다. 이 단계를 건너뛰거나 코드베이스에서 컨텍스트를 유추하려 하지 마세요.

## 디자인 방향

과감한(BOLD) 미적 방향을 결정합니다:
- **목적**: 이 인터페이스가 해결하는 문제는? 누가 사용하는가?
- **톤**: 극단적인 방향을 선택합니다: 극도의 미니멀, 맥시멀리스트 카오스, 레트로 퓨처리즘, 유기적/자연적, 럭셔리/세련됨, 장난스러움/토이, 에디토리얼/매거진, 브루탈리스트/로우, 아르데코/기하학적, 소프트/파스텔, 산업적/실용적 등. 선택지는 무궁무진합니다. 이들을 영감으로 삼되 미적 방향에 충실한 디자인을 만드세요.
- **제약**: 기술적 요구사항 (프레임워크, 성능, 접근성).
- **차별화**: 무엇이 이것을 잊을 수 없게 만드는가? 누군가가 기억할 단 하나는?

**핵심**: 명확한 컨셉 방향을 정하고 정밀하게 실행합니다. 대담한 맥시멀리즘과 세련된 미니멀리즘 모두 유효합니다 — 핵심은 강렬함이 아니라 의도성입니다.

그런 다음 다음 조건을 충족하는 작동하는 코드를 구현합니다:
- 프로덕션 수준의 기능성
- 시각적으로 인상적이고 기억에 남는 디자인
- 명확한 미적 관점을 가진 일관된 디자인
- 모든 디테일이 세심하게 다듬어진 결과물

## 프론트엔드 미학 가이드라인

### 타이포그래피(Typography)
→ *타이포그래피 스케일, 조합, 로딩 전략은 [typography reference](reference/typography.md) 참조.*

아름답고 독특하며 흥미로운 폰트를 선택합니다. 특색 있는 디스플레이 폰트와 세련된 본문 폰트를 조합합니다.

**이렇게 하세요**: 유동적 사이즈(clamp)와 함께 모듈러 타입 스케일을 사용
**이렇게 하세요**: 폰트 굵기와 크기를 다양하게 하여 명확한 시각적 위계를 만듦
**이러지 마세요**: 과도하게 사용된 폰트 — Inter, Roboto, Arial, Open Sans, 시스템 기본 폰트
**이러지 마세요**: 모노스페이스 타이포그래피를 "기술적/개발자" 느낌의 안이한 수단으로 사용
**이러지 마세요**: 모든 제목 위에 둥근 모서리의 큰 아이콘 배치 — 가치를 더하는 경우가 드물고 템플릿처럼 보임

### 색상 및 테마
→ *OKLCH, 팔레트, 다크 모드는 [color reference](reference/color-and-contrast.md) 참조.*

일관된 팔레트를 확립합니다. 강렬한 주색과 날카로운 액센트의 조합이 소극적이고 균등 분배된 팔레트보다 효과적입니다.

**이렇게 하세요**: 현대적 CSS 색상 함수(oklch, color-mix, light-dark)로 지각적으로 균일하고 유지보수가 용이한 팔레트 구축
**이렇게 하세요**: 뉴트럴 색상에 브랜드 색조를 살짝 입혀 무의식적 일관성 생성
**이러지 마세요**: 색상 배경 위에 회색 텍스트 사용 — 바랜 느낌; 배경색의 셰이드를 사용
**이러지 마세요**: 순수 블랙(#000)이나 순수 화이트(#fff) 사용 — 항상 색조를 입히세요; 자연에는 순수 흑백이 존재하지 않음
**이러지 마세요**: AI 색상 팔레트 사용: 다크 배경에 시안, 퍼플-투-블루 그라데이션, 다크 배경에 네온 액센트
**이러지 마세요**: "임팩트"를 위한 그라데이션 텍스트 — 특히 지표나 제목에; 의미 전달이 아닌 장식
**이러지 마세요**: 빛나는 액센트의 다크 모드를 기본값으로 — 실제 디자인 결정 없이 "멋져 보이기"만 함

### 레이아웃 및 공간
→ *그리드, 리듬, 컨테이너 쿼리는 [spatial reference](reference/spatial-design.md) 참조.*

다양한 간격을 통해 시각적 리듬을 만듭니다 — 어디나 같은 패딩이 아닌. 비대칭과 예상치 못한 구성을 적극 활용합니다. 강조를 위해 의도적으로 그리드를 깹니다.

**이렇게 하세요**: 다양한 간격으로 시각적 리듬 생성 — 촘촘한 그룹핑, 넉넉한 분리
**이렇게 하세요**: clamp()로 유동적 간격을 사용하여 큰 화면에서 여유롭게
**이렇게 하세요**: 비대칭과 예상치 못한 구성 활용; 강조를 위해 의도적으로 그리드를 깸
**이러지 마세요**: 모든 것을 카드로 감싸기 — 모든 것에 컨테이너가 필요하지 않음
**이러지 마세요**: 카드 안에 카드 중첩 — 시각적 노이즈, 위계를 평탄화
**이러지 마세요**: 동일한 카드 그리드 — 아이콘 + 제목 + 텍스트의 같은 크기 카드 반복
**이러지 마세요**: 히어로 지표 레이아웃 템플릿 — 큰 숫자, 작은 레이블, 부가 통계, 그라데이션 액센트
**이러지 마세요**: 모든 것을 가운데 정렬 — 비대칭 레이아웃에 왼쪽 정렬 텍스트가 더 디자인된 느낌
**이러지 마세요**: 어디나 같은 간격 — 리듬 없이는 레이아웃이 단조로움

### 비주얼 디테일
**이렇게 하세요**: 브랜드를 강화하는 의도적이고 목적 있는 장식 요소 사용
**이러지 마세요**: 글래스모피즘(Glassmorphism)을 남용 — 블러 효과, 유리 카드, 글로우 보더를 목적 없이 장식적으로 사용
**이러지 마세요**: 한 면에 두꺼운 컬러 보더가 있는 둥근 요소 — 의도적으로 보이는 경우가 거의 없는 안이한 액센트
**이러지 마세요**: 장식용 스파크라인 — 세련돼 보이지만 의미 있는 정보를 전달하지 않는 작은 차트
**이러지 마세요**: 뻔한 드롭 섀도가 있는 둥근 직사각형 — 안전하고 기억에 남지 않으며 어떤 AI 출력이든 될 수 있음
**이러지 마세요**: 진정으로 더 나은 대안이 없는 경우가 아니면 모달 사용 — 모달은 안이한 선택

### 모션(Motion)
→ *타이밍, 이징, 모션 감소 대응은 [motion reference](reference/motion-design.md) 참조.*

고영향 순간에 집중합니다: 시차를 둔 공개가 포함된 하나의 잘 조율된 페이지 로드가 산발적인 마이크로 인터랙션보다 더 큰 즐거움을 줍니다.

**이렇게 하세요**: 상태 변화를 전달하기 위해 모션 사용 — 진입, 퇴장, 피드백
**이렇게 하세요**: 자연스러운 감속을 위한 지수 이징(ease-out-quart/quint/expo) 사용
**이렇게 하세요**: 높이 애니메이션에는 height를 직접 애니메이션하지 않고 grid-template-rows 트랜지션 사용
**이러지 마세요**: 레이아웃 속성(width, height, padding, margin) 애니메이션 — transform과 opacity만 사용
**이러지 마세요**: 바운스나 일래스틱 이징 — 촌스럽고 구식; 실제 물체는 부드럽게 감속

### 인터랙션(Interaction)
→ *폼, 포커스, 로딩 패턴은 [interaction reference](reference/interaction-design.md) 참조.*

인터랙션이 빠르게 느껴지도록 합니다. 낙관적 UI(Optimistic UI)를 사용합니다 — 즉시 업데이트하고 나중에 동기화.

**이렇게 하세요**: 점진적 공개(Progressive Disclosure) 사용 — 단순하게 시작하고 인터랙션을 통해 복잡성을 드러냄 (기본 옵션 먼저, 고급 옵션은 확장 가능 섹션 뒤에; 호버 시 부가 액션 노출)
**이렇게 하세요**: 빈 상태에서 "여기에 아무것도 없습니다"가 아닌 인터페이스 사용법을 알려주는 디자인
**이렇게 하세요**: 모든 인터랙티브 표면이 의도적이고 반응적으로 느껴지도록
**이러지 마세요**: 같은 정보를 반복 — 제목을 되풀이하는 중복 헤더와 소개문
**이러지 마세요**: 모든 버튼을 프라이머리로 — 고스트 버튼, 텍스트 링크, 세컨더리 스타일을 활용; 위계가 중요

### 반응형(Responsive)
→ *모바일 퍼스트, 유동적 디자인, 컨테이너 쿼리는 [responsive reference](reference/responsive-design.md) 참조.*

**이렇게 하세요**: 컴포넌트 단위 반응형을 위해 컨테이너 쿼리(@container) 사용
**이렇게 하세요**: 다른 맥락에 맞게 인터페이스를 적응 — 단순히 축소하지 않음
**이러지 마세요**: 모바일에서 핵심 기능 숨기기 — 인터페이스를 적응시키지, 절단하지 않음

### UX 라이팅(UX Writing)
→ *레이블, 에러, 빈 상태는 [ux-writing reference](reference/ux-writing.md) 참조.*

**이렇게 하세요**: 모든 단어가 존재 이유를 증명하게
**이러지 마세요**: 사용자가 이미 볼 수 있는 정보를 반복

## AI 양산형 테스트

**핵심 품질 점검**: 이 인터페이스를 누군가에게 보여주며 "AI가 만들었다"고 하면 즉시 믿을까요? 그렇다면, 그것이 문제입니다.

차별화된 인터페이스는 "어떤 AI가 만들었지?"가 아니라 "이걸 어떻게 만들었지?"라는 질문을 이끌어내야 합니다.

위의 "이러지 마세요" 가이드라인을 검토하세요 — 이것들이 2024-2025 AI 생성 작업의 지문입니다.

## 구현 원칙

구현의 복잡도를 미적 비전에 맞춥니다. 맥시멀리스트 디자인은 방대한 애니메이션과 효과가 포함된 정교한 코드가 필요합니다. 미니멀리스트나 세련된 디자인은 절제, 정밀함, 간격·타이포그래피·미묘한 디테일에 대한 세심한 주의가 필요합니다.

창의적으로 해석하고 맥락에 진정으로 맞게 디자인된 느낌의 예상치 못한 선택을 합니다. 어떤 디자인도 같아서는 안 됩니다. 라이트와 다크 테마, 다른 폰트, 다른 미학을 번갈아 사용합니다. 생성 간에 흔한 선택으로 수렴하지 마세요.

기억하세요: Claude는 놀라운 창의적 작업이 가능합니다. 주저하지 마세요 — 틀 밖에서 사고하고 차별화된 비전에 온전히 몰입할 때 진정으로 무엇을 만들 수 있는지 보여주세요.
