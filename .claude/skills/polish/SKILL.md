## 필수 준비

/frontend-design을 호출한다 — 디자인 원칙, 안티패턴, **컨텍스트 수집 프로토콜**이 포함되어 있다. 프로토콜을 따른다 — 디자인 컨텍스트가 아직 없으면 /teach-impeccable을 먼저 실행한다. 추가로 품질 기준(MVP vs 플래그십)을 파악한다.

---

좋은 작업과 훌륭한 작업을 가르는 모든 작은 디테일을 잡아내는 세심한 최종 패스를 수행한다. 완성된 것과 다듬어진 것의 차이다.

**예시:**
입력: "/polish 타워 선택 패널"
출력: 완성도 검토 → 12개 차원 체계적 다듬기 → 체크리스트 점검 → 최종 검증

## 다듬기 전 평가

현재 상태와 목표를 파악한다:

1. **완성도 검토**: 기능적으로 완성됐는가? TODO가 남아 있는가? 품질 기준은? (MVP vs 플래그십?) 출시까지 시간은?
2. **다듬기 영역 식별**: 시각적 불일치, 간격 및 정렬 이슈, 인터랙션 상태 공백, 문구 불일치, 엣지 케이스와 에러 상태, 로딩 및 트랜지션 매끄러움

다듬기는 마지막 단계이지 첫 번째가 아니다 — 기능적으로 완성되지 않은 작업을 다듬으면 나중에 기능 변경 시 다듬기 작업이 무효화되기 때문이다.

## 체계적으로 다듬기

다음 차원을 순서대로 작업한다:

### 시각적 정렬 및 간격

- **픽셀 완벽 정렬**: 모든 것이 그리드에 맞춤
- **일관된 간격**: 모든 갭이 간격 스케일을 사용 (임의의 13px 갭 없음)
- **시각적 정렬(Optical Alignment)**: 시각적 무게에 맞게 조정 (아이콘은 시각적 중심을 맞추기 위해 오프셋이 필요할 수 있음)
- **반응형 일관성**: 모든 브레이크포인트에서 간격과 정렬이 작동
- **그리드 준수**: 요소가 베이스라인 그리드에 맞춤

### 타이포그래피 정제

- **위계 일관성**: 같은 요소가 전체에서 같은 크기/굵기 사용
- **줄 길이**: 본문 텍스트 45-75자
- **줄 높이**: 폰트 크기와 맥락에 적합
- **과부(Widows) 및 고아(Orphans)**: 마지막 줄에 단어 하나만 남지 않도록
- **자간(Kerning)**: 필요한 곳에서 글자 간격 조정 (특히 헤드라인)
- **폰트 로딩**: FOUT/FOIT 깜빡임 없음

### 색상 및 대비

- **대비율**: 모든 텍스트가 WCAG 표준 충족
- **일관된 토큰 사용**: 하드코딩된 색상 없이 모두 디자인 토큰 사용
- **테마 일관성**: 모든 테마 변형에서 작동
- **색상 의미**: 같은 색상이 전체에서 같은 의미
- **접근 가능한 포커스**: 충분한 대비의 포커스 인디케이터
- **색조 뉴트럴(Tinted Neutrals)**: 순수 회색이나 순수 검정 대신 미묘한 색조 추가 — 자연에는 순수 뉴트럴이 없으므로 미세한 색조가 따뜻함을 준다
- **색상 위 회색 금지**: 색상 배경에 회색 텍스트 대신 해당 색상의 셰이드나 투명도를 사용한다 — 회색이 색상 위에 올라가면 바래 보이기 때문이다

### 인터랙션 상태

모든 인터랙티브 요소에 전체 상태가 필요하다 — 누락된 상태는 혼란과 깨진 경험을 만든다:

- **기본(Default)**: 대기 상태
- **호버(Hover)**: 미묘한 피드백 (색상, 스케일, 그림자)
- **포커스(Focus)**: 키보드 포커스 인디케이터 — 제거하면 키보드 사용자가 현재 위치를 잃는다
- **활성(Active)**: 클릭/탭 피드백
- **비활성(Disabled)**: 명확히 비인터랙티브
- **로딩(Loading)**: 비동기 액션 피드백
- **에러(Error)**: 유효성 검사 또는 에러 상태
- **성공(Success)**: 완료 확인

### 마이크로 인터랙션 및 트랜지션

- **매끄러운 트랜지션**: 모든 상태 변화가 적절히 애니메이션 (150-300ms)
- **일관된 이징**: 자연스러운 감속을 위해 ease-out-quart/quint/expo 사용 — 바운스나 일래스틱은 실제 물체의 운동과 맞지 않아 구식 느낌을 준다
- **60fps 유지**: transform과 opacity만 애니메이션
- **적절한 모션**: 모션은 장식이 아닌 목적에 부합
- **모션 감소 대응**: `prefers-reduced-motion` 존중

### 콘텐츠 및 문구

- **일관된 용어**: 같은 것을 전체에서 같은 이름으로
- **일관된 대소문자**: 타이틀 케이스 vs 문장 케이스 일관 적용
- **문법 및 맞춤법**: 오타 없음
- **적절한 길이**: 너무 장황하지도 너무 간결하지도 않게
- **구두점 일관성**: 문장에는 마침표, 레이블에는 없음

### 아이콘 및 이미지

- **일관된 스타일**: 모든 아이콘이 같은 패밀리 또는 일치하는 스타일
- **적절한 크기와 정렬**: 아이콘이 인접 텍스트와 시각적으로 정렬
- **대체 텍스트**: 모든 이미지에 설명적 대체 텍스트
- **로딩 상태**: 이미지가 레이아웃 시프트를 유발하지 않음, 적절한 종횡비
- **레티나 지원**: 고해상도 화면을 위한 2x 에셋

### 폼 및 입력

- **레이블 일관성**: 모든 입력에 적절한 레이블
- **필수 표시**: 명확하고 일관
- **에러 메시지**: 도움이 되고 일관
- **탭 순서**: 논리적 키보드 내비게이션
- **유효성 검사 타이밍**: 일관 (blur 시 vs submit 시)

### 엣지 케이스 및 에러 상태

- **로딩 상태**: 모든 비동기 액션에 로딩 피드백
- **빈 상태**: 빈 공간이 아닌 도움이 되는 빈 상태
- **에러 상태**: 복구 경로가 있는 명확한 에러 메시지
- **긴 콘텐츠**: 매우 긴 이름, 설명 등 처리
- **콘텐츠 없음**: 데이터 누락을 우아하게 처리

### 반응형

- **모든 브레이크포인트**: 모바일, 태블릿, 데스크톱 테스트
- **터치 타겟**: 터치 기기에서 최소 44x44px
- **가독성 있는 텍스트**: 모바일에서 14px 미만 텍스트 없음
- **가로 스크롤 없음**: 콘텐츠가 뷰포트에 맞음

### 성능

- **빠른 초기 로드**: 크리티컬 패스 최적화
- **레이아웃 시프트 없음**: 로드 후 요소가 점프하지 않음 (CLS)
- **매끄러운 인터랙션**: 지연이나 버벅임 없음
- **최적화된 이미지**: 적절한 포맷과 크기
- **지연 로딩(Lazy Loading)**: 화면 밖 콘텐츠는 지연 로딩

### 코드 품질

- **console.log 제거**: 프로덕션에 디버그 로그 없음
- **주석 처리된 코드 제거**: 죽은 코드 정리
- **미사용 임포트 제거**: 미사용 의존성 정리
- **일관된 명명**: 변수와 함수가 컨벤션 준수
- **타입 안전성**: TypeScript `any` 또는 무시된 에러 없음
- **접근성**: 적절한 ARIA 레이블과 시맨틱 HTML

## 다듬기 품질 원칙

기능적으로 완성되기 전에 다듬기 시작하면 기능 변경이 다듬기 작업을 무효화한다. 시간이 촉박할 때는 트리아지한다 — 30분 후 출시인데 몇 시간짜리 다듬기를 하면 안 된다. 다듬으면서 버그를 도입하지 않도록 철저히 테스트한다. 간격이 어디서나 어긋나면 개별 수정이 아니라 시스템을 수정한다 — 체계적 문제에는 체계적 해결이 필요하다. 하나만 완벽하게 하고 나머지를 거칠게 방치하지 않는다 — 일관된 품질 수준이 전체적 인상을 결정하기 때문이다.

## 최종 검증

완료 표시 전:

- **직접 사용해 보기**: 실제로 기능과 상호작용
- **실제 기기에서 테스트**: 브라우저 DevTools만이 아닌
- **다른 사람에게 리뷰 요청**: 새로운 눈이 놓친 것을 발견
- **디자인과 비교**: 의도한 디자인과 일치하는지
- **모든 상태 점검**: 해피 패스만 테스트하지 않기

사용하기에 자연스럽고, 의도적으로 보이며, 완벽하게 작동할 때까지 다듬는다. 디테일에 땀을 흘린다 — 그것이 좋은 것과 훌륭한 것의 차이다.
